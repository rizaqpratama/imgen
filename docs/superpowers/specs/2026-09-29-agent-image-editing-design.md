# Agent image editing

## Goal

Add a conversational image workspace to Sunburst Studio. A user can create an image, request successive edits, and keep the image history in one thread. GPT-6 Luna or GPT-6 Sol plans each turn and invokes OpenAI's Responses API `image_generation` tool. Luna is the default.

The existing Generate, Turnaround, Catalog, Gallery, and Key views remain available.

## User experience

Add an **Agent** item before Generate in the navigation. The workspace contains:

- a thread list with create, rename, and delete actions;
- a timeline of user requests, agent plans, and generated images;
- a composer for the next instruction;
- a GPT-6 Luna/Sol selector stored per thread;
- an Auto-generate toggle stored per thread;
- manually pinned character references from the catalog;
- quality and size controls;
- an editable plan card showing the expanded prompt and references before generation when Auto-generate is off.

The first turn may be text-to-image. A user can also begin from a gallery image. Later turns use the latest successful image in the thread as the edit source. Every successful image is also added to the existing gallery.

## Turn lifecycle

### Planning

The server sends GPT-6:

- the user's instruction;
- a compact catalog manifest containing character IDs, names, and notes;
- the thread's current scene summary;
- the IDs of manually pinned references;
- the latest image metadata, when present.

GPT-6 returns a structured plan:

- `summary`: a short explanation shown in the timeline;
- `expandedPrompt`: complete image instructions;
- `scene`: subject, setting, composition, camera, lighting, and style details;
- `preserve`: details that must not drift from the current image;
- `referenceIds`: selected catalog character IDs.

Pinned references are always included. The server rejects unknown IDs and removes duplicates. The agent selects references from metadata; only selected image files are subsequently sent to the image tool, so a large catalog does not inflate every image request.

When Auto-generate is disabled, the client shows the plan. The user may edit the expanded prompt and add or remove references before approving it. When Auto-generate is enabled, the server executes the plan immediately and returns both the plan and result.

### Image execution

Execution uses the OpenAI Responses API with the thread's GPT-6 model and:

```json
{
  "tools": [{ "type": "image_generation", "action": "auto" }]
}
```

The request includes the approved expanded prompt, the latest generated image when editing, and selected catalog images. The prompt explicitly labels image order:

- image 1: current canvas, when present;
- following images: named character references.

The server stores the Responses API response ID, image-generation call ID, generated image, and revised prompt returned by OpenAI. A follow-up turn supplies `previous_response_id` when valid. The latest image is also supplied explicitly for resilience and reproducibility. If OpenAI can no longer continue a stored response, the server retries once without `previous_response_id`, using the stored scene summary and latest image.

## Persistence

Extend `data/db.json` with:

- `agentThreads`: thread identity, title, model, auto-generate setting, selected quality and size, pinned reference IDs, latest response ID, and timestamps;
- `agentTurns`: thread ID, user instruction, status, plan, approved prompt, chosen references, response ID, image call ID, generation ID, revised prompt, error, and timestamps.

Generated bytes continue to live in `data/gallery`. Agent generations use a new `agent` generation kind, so they appear in the Gallery's Agent filter and retain thread/turn metadata.

Plans waiting for approval are durable. Reloading the app must not discard them. A failed turn remains visible and can be retried. Deleting a thread removes its turn records but does not delete gallery images.

## Server boundaries

Create focused modules:

- `server/src/agent.ts`: GPT-6 planning, structured-output validation, Responses image-tool execution, and retry behavior;
- `server/src/agent-prompts.ts`: planner instructions and explicit image-order prompt construction;
- `server/src/store.ts`: thread and turn types plus persistence helpers;
- `server/src/index.ts`: HTTP validation and routing only.

Add endpoints:

- `GET/POST /api/agent/threads`;
- `GET/PATCH/DELETE /api/agent/threads/:id`;
- `GET /api/agent/threads/:id/turns`;
- `POST /api/agent/threads/:id/turns` to plan a turn and optionally execute it;
- `PATCH /api/agent/turns/:id/plan` to edit a pending plan;
- `POST /api/agent/turns/:id/generate` to approve and execute;
- `POST /api/agent/turns/:id/retry`.

All IDs are validated. Model values are limited to `gpt-6-luna` and `gpt-6-sol`. Reference IDs must exist. The server continues to read the API key from local settings and never exposes it to the client.

## Client boundaries

Add:

- `client/src/views/Agent.tsx`: workspace layout and orchestration;
- `client/src/components/ThreadList.tsx`;
- `client/src/components/AgentTimeline.tsx`;
- `client/src/components/AgentComposer.tsx`;
- `client/src/components/AgentPlanCard.tsx`;
- typed Agent records and API helpers in `client/src/api.ts`.

The desktop layout uses a compact thread rail, timeline, and right-side reference tray. On a narrow screen these become a thread dropdown, timeline, and collapsible reference tray. Pending and running turns disable duplicate submission but leave thread navigation usable.

## Errors and safety

- Planning and generation have separate statuses and error messages.
- A planning error creates no image request.
- An image-tool response without an image is treated as a failed turn and its text response is shown.
- The API enforces prompt lengths, valid image formats, known references, and one active operation per thread.
- The client never claims a turn succeeded before a gallery file and database record are both written.
